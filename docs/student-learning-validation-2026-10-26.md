# 学生学习流程：实现与验收记录

日期：2026-10-26。分支：`feat/student-learning`。本轮在本机静态服务验收，未发布线上。

## 实现范围

学生可从一道学校作业中的错题或当前章节进入。照片在浏览器本地做印刷文字 OCR；核对文字、说明自己的尝试及卡点后，人工确认知识点候选。候选来自本地名称、词语和简单算式形式匹配，不是经过校准的题意理解或错因判断。练习、标准和解析来自仓库原有题库，不为任意上传题目生成解答。

记录区分首次独立正确、使用帮助、错误、不会、同题重复及原题重做。参考答案在提交后打开，不改写原始提交条件；提交前查看帮助则需要换题独立检查。评分可更正，原答案保留。已看答案和已答题按学习者、学科避让；相关知识点在别的任务中的近期作答也会重算复查间隔。

诊断默认使用 `evidence-v1`：一道正确答案不再带来全部祖先的推断掌握，证据不足保留未验证，只沿硬先修继续检查。每点最多三题、两次独立正确的门槛是待检验的产品规则。v2 历史重放显式保留旧规则，不混入新汇总。进度与档案保存失败均有提示。

## 自动检查

- `npm test`：89 项旧版兼容测试、10 项新证据测试、学习记录边界检查、诊断反馈及存档恢复检查通过。
- 学习模型检查包括：同题与不同题、帮助条件、日期合法性、真实间隔、跨任务相关活动、其他孩子/学科隔离、历史更正和删除、题库用尽、公式候选及原题避让。
- `python scripts/validate.py`：2313 个知识点、3571 条边、9399 道题通过数据校验。原数据仍有 2 个知识点缺少课标映射的警告：`cnm_130`、`cnm_192`。
- 修改脚本通过 Node 语法检查，`git diff --check` 通过。OCR 发行文件按清单核对 SHA-256；下载脚本核对 npm SHA-512 完整性。

## 浏览器实际操作

通过本机 `http://127.0.0.1:8765/learn/` 完成以下操作：

1. 上传合成的中文印刷题图片 `tests/fixtures/ocr-printed-question.png`；识别出题干和 `2x+3=7`，勾选核对后选取相关知识点、保存任务。
2. 首次独立答对记录为独立正确；提交后打开解析不改写该条件。下一题先看答案后答对记录为借助帮助。
3. 查看样题后刷新，再提交仍记为借助帮助；样题展开后保持可读。修改输入题目后必须重新确认知识点。
4. 人工改判同步更新当前反馈与历史；刷新保留记录、当前题目和帮助条件。JSON 导出保留 `support`、题号、作答和曝光记录。
5. 切到英语不显示数学任务；从英语章节选知识点可以抽取真实题库题，返回数学恢复原任务。
6. 在 390 × 844 视口检查入口及练习页，没有横向溢出；测试后恢复正常视口。
7. 浏览器模拟断网后刷新，已缓存的学习页面、数学任务和题库恢复成功；测试后还原网络。
8. 诊断页在查看参考答案后刷新保留帮助状态；题量上限为 1 时没有判为本次通过或受阻。分享图生成成功，使用当前证据标签。

## 尚未验证的部分

本轮是软件功能验收，没有学生学习效果试验。手写、复杂公式、几何图形识别和开放解答质量没有得到验证；OCR 结果必须核对。现有题库未经教师全面审校且每点仅 4–5 题，用尽会明确提示。复查默认 3 天，可调整，不是根据个人数据拟合的遗忘曲线；趋势只显示有记录的作答次数。

本机数据不会跨设备自动同步；清除网站数据会清除本机记录和照片。离线能力依赖先前缓存，OCR 首次使用需能读取随仓库提供的组件文件。

研究依据、核读范围与因果证据的边界见[学习科学研究记录](learning-science-review-2026-10-26.md)。
